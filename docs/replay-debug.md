# Replay / Debug（Phase 13）

Replayで「WAVを開く」→「Timelineを解析」を押すと、全区間の発音候補を一覧表示します。
ラウンドの状態に関係なく、後続の不確かな音も確認できます。
両PASSの照合と確定順は、従来の「順序を解析」で確認します。

## 操作

1. Timelineの行を選び、時刻、長さ、Oracle / unknown、信頼度、各スコア、理由を確認します。
2. 直下の候補表で全7種類の順位と候補差を確認します。「スコア内訳を表示」で波形・スペクトルを展開します。
3. 「選択音をListen」で元形式の切り出し音声を再生します。音量は20%、再生停止で中断できます。
4. 同じWAVを再解析し、音声の一致メッセージと条件IDを確認します。
5. 正解が分かったら「誤認識・確認用の音声を保存」を開き、[手動の正解付け](gameplay-review.md)を行います。

時刻は元WAV先頭からの発音開始、長さは検出信号の長さです。
Listenには前後の余裕を含む窓を使います。行の説明には元フレーム範囲と第1候補があります。
スコアは類似度です。LOW / REJECTEDでも候補と内訳を残し、Oracleはunknownにします。

## 再現条件と制限

結果には内部レート、認識設定、帯域、集約方式・重み、元テンプレートの識別子とchecksumを保存します。
条件IDの説明から内容を確認できます。解析中のテンプレート変更では結果を採用せず、再解析を案内します。

通常のWAVは毎回読み直します。Liveの認識イベントとログから開いた音声は固定コピーで再解析できます。
ログに元音声checksumがある場合は開く際に検証します。
読込失敗時は古いTimeline・候補・音声保存を消去します。

入力は120秒以内、検出候補128件まで、1窓は3秒 / 16 MiB以内です。
短すぎる音、録音の先頭・終端で切れた音、上限を超える音はunknownです。
長い録音は分割してください。WAV形式・サイズは[README](../README.md)と共通です。
解析・再生・保存は取得とは別の既存ワーカーで処理します。

提供音声から組んだRound 5の14音、反復解析の一致、全7候補、元形式の再生区間、
ログchecksumとLive固定コピーをWindowsの100% / 150%表示で確認しました。
実戦の受け入れ範囲は[acceptance.md](acceptance.md)を参照してください。
